Key Findings
Critical Event Duplication (Double-Firing): Every single user interaction (page_view, view_item, add_to_cart, purchase) is currently dispatched twice to Google Analytics. The analytics.js helper functions call ReactGA.event(...) and window.gtag('event', ...) simultaneously. Because react-ga4 internally delegates to window.gtag, every event is logged as two separate hits in GA4.
Dual Tag Initialization: index.html loads the static gtag.js script tag for G-WRRBVHX7NT and calls gtag('config') on raw page load, while App.jsx calls ReactGA.initialize('G-WRRBVHX7NT') which injects a second gtag.js tag. This creates triple-firing of initial page_view hits.
Hardcoded Configuration: GA_MEASUREMENT_ID (G-WRRBVHX7NT) is hardcoded directly in analytics.js and index.html rather than being loaded from environment variables (import.meta.env.VITE_GA_MEASUREMENT_ID), preventing multi-environment deployment (dev/staging/prod).
Incomplete GA4 Ecommerce Funnel: Core ecommerce funnel events required for GA4 Ecommerce conversion reports and PlanPost Monetization dashboards (view_item_list, select_item, view_cart, remove_from_cart, begin_checkout, add_shipping_info) are completely missing.
Data Corruption Risk: In trackPurchase, missing order fields fall back to hardcoded test data ("PlanPost Hoodie", $79.99, "txn_001"), which will corrupt actual store revenue analytics if malformed payloads pass through.
Overall Recommendation
DO NOT approve the current E-commerce implementation as the reference standard in its current state.
The ecommerce app must be updated with the recommended clean single-source analytics architecture outlined in this report before using it as the blueprint for PlanPost.

2. Current Analytics Architecture
The e-commerce application uses a React (Vite) single-page application frontend. Analytics events are currently triggered via a hybrid setup:

[User Browser]
   │
   ├──> index.html (Static gtag.js script tag -> G-WRRBVHX7NT)
   │       └──> Automatic pageview on initial HTML load
   │
   └──> App.jsx (React SPA mount)
           └──> initGA() -> ReactGA.initialize('G-WRRBVHX7NT')
           │       └──> Injects 2nd gtag.js script tag
           │
           └──> useEffect([location]) -> trackPageView()
                   ├──> 1. ReactGA.send({ hitType: 'pageview' }) ──> GA4 Server Hit #1
                   └──> 2. window.gtag('config', 'G-WRRBVHX7NT') ──> GA4 Server Hit #2
Event Flow Breakdown
Script Load: When index.html loads, Google Tag (G-WRRBVHX7NT) is loaded and fires an initial page_view.
App Mount: App.jsx executes initGA() in a top-level useEffect, initializing react-ga4.
Route Navigation: useLocation() in AppContent fires trackPageView(...) on every route change.
User Actions:
Viewing a product (ProductDetails.jsx) calls trackViewItem(product).
Clicking Add to Cart (ProductCard.jsx, ProductDetails.jsx) calls trackAddToCart(product, quantity).
Payment success (CheckoutRedirects.jsx) calls trackPurchase(order).
3. Verified Working Components
The following aspects of the current implementation are conceptually sound and should be retained:

SPA Route Tracking via React Router Hooks: Using useLocation() inside an AppContent component wrapped by <Router> is the correct React pattern to capture SPA page navigation without full page reloads.
Error Isolation: Utility functions in analytics.js encapsulate tracking logic inside try...catch blocks, ensuring that any analytics failures or network errors do not crash the React UI.
Structured Data Helper Functions: Centralizing event dispatches in a dedicated helper file (analytics.js) rather than placing raw gtag calls directly inside components is good architectural practice.
Asynchronous Order Fetching on Checkout Redirect: CheckoutRedirects.jsx properly fetches complete order details from the backend (/api/v1/orders/:id) before triggering trackPurchase(order).
4. Problems Found
Issue 1: Double-Firing / Duplicate Events (Critical)
Severity: Critical
Root Cause: In frontend/src/utils/analytics.js, every tracking function calls both ReactGA and window.gtag. For example:
// analytics.js L15-18
ReactGA.send({ hitType: 'pageview', page: path });
if (typeof window !== 'undefined' && typeof window.gtag === 'function') {
  window.gtag('config', GA_MEASUREMENT_ID, { page_path: path });
}
ReactGA already wraps window.gtag. Calling both causes gtag to execute twice for every action.
Evidence: Inspected analytics.js lines 15-18, 34-46, 63-75, 103-117.
Impact: 100% inflation of event counts, active page views, and monetization revenue in GA4 reports and PlanPost API data.
Recommendation: Remove all explicit window.gtag calls from analytics.js and rely exclusively on ReactGA.
Issue 2: Hardcoded Measurement ID & Lack of Environment Variable Support (High)
Severity: High
Root Cause: GA_MEASUREMENT_ID = 'G-WRRBVHX7NT' is hardcoded as a literal string in analytics.js and index.html.
Evidence: Inspected frontend/src/utils/analytics.js line 3 and frontend/index.html lines 13, 19.
Impact: Cannot switch GA4 properties across local development, staging, and production without modifying source code. Local testing pollutes live GA4 data.
Recommendation: Move Measurement ID to .env as VITE_GA_MEASUREMENT_ID.
Issue 3: Dual Initialization in HTML and JS (High)
Severity: High
Root Cause: GA4 script is initialized twice: once via static <script> in index.html and once via ReactGA.initialize() in App.jsx.
Evidence: index.html lines 12-20 contains a complete gtag.js installation snippet. App.jsx line 94 calls initGA().
Impact: Creates duplicate script DOM elements and double-configures GA4 on initial load.
Recommendation: Remove the gtag.js snippet from index.html completely; let ReactGA.initialize() manage script loading dynamically in JavaScript.
Issue 4: Missing GA4 Recommended Ecommerce Events (High)
Severity: High
Root Cause: Only 3 ecommerce events (view_item, add_to_cart, purchase) are implemented.
Evidence: Checked all usages of analytics.js across the codebase using grep_search.
Impact: Full funnel conversion tracking (Item List -> View Item -> Add to Cart -> View Cart -> Begin Checkout -> Add Shipping -> Purchase) cannot be visualized in GA4 or PlanPost.
Recommendation: Implement view_item_list, select_item, view_cart, remove_from_cart, begin_checkout, add_shipping_info, and add_payment_info.
Issue 5: Hardcoded Fallback Dummy Data in trackPurchase (Medium)
Severity: Medium
Root Cause: trackPurchase falls back to static test values when order fields are missing:
// analytics.js L94 & L98
: [{ item_id: 'sku_123', item_name: 'PlanPost Hoodie', price: 79.99, quantity: 1 }];
Evidence: Inspected analytics.js lines 94, 98, 100.
Impact: If an order payload fails to load or has missing properties, fake sales of "PlanPost Hoodie" ($79.99) are logged into production analytics.
Recommendation: If order or order.items is invalid, log an error and abort tracking instead of sending dummy fallback data.
Issue 6: Incomplete Item Parameter Schema (Medium)
Severity: Medium
Root Cause: Item arrays in view_item, add_to_cart, and purchase omit standard GA4 fields such as item_category, item_brand, and currency.
Evidence: trackViewItem lines 27-31 only pass item_id, item_name, and price.
Impact: GA4 Category and Brand performance reports remain empty.
Recommendation: Include item_category, item_brand, and currency in item mappings.
Issue 7: Lack of DebugView Compatibility (debug_mode) (Low)
Severity: Low
Root Cause: ReactGA.initialize() is called without gaOptions or gtagOptions to enable debug_mode.
Evidence: analytics.js line 7: ReactGA.initialize(GA_MEASUREMENT_ID);.
Impact: Developer events cannot be filtered or inspected live in Google Analytics DebugView without a browser extension.
Recommendation: Enable debug_mode: true in non-production environments.

import ReactGA from 'react-ga4';

export const GA_MEASUREMENT_ID = import.meta.env.VITE_GA_MEASUREMENT_ID || 'G-WRRBVHX7NT';

/**
 * Initialize Google Analytics 4
 */
export const initGA = () => {
  if (!GA_MEASUREMENT_ID) {
    console.warn('GA4 Measurement ID is missing.');
    return;
  }
  try {
    const isDev = import.meta.env.DEV;
    ReactGA.initialize(GA_MEASUREMENT_ID, {
      gaOptions: {
        debug_mode: isDev,
      },
    });
    console.log(`GA4 initialized with ID: ${GA_MEASUREMENT_ID} (debug_mode: ${isDev})`);
  } catch (err) {
    console.error('Failed to initialize ReactGA:', err);
  }
};

/**
 * Track SPA Page View
 */
export const trackPageView = (path) => {
  try {
    ReactGA.send({ hitType: 'pageview', page: path });
  } catch (err) {
    console.error('Error tracking pageview:', err);
  }
};

/**
 * Format item object according to GA4 Ecommerce Schema
 */
const formatGA4Item = (product, quantity = 1) => {
  if (!product) return null;
  const price = typeof product.price === 'number' ? product.price : parseFloat(product.price) || 0;
  return {
    item_id: String(product._id || product.id || product.sku || 'unknown_item'),
    item_name: product.name || 'Product',
    item_category: product.category || 'General',
    item_brand: product.brand || 'Apex',
    price: price,
    quantity: quantity,
  };
};

/**
 * Track view_item_list (Browsing Product Catalog / Shop)
 */
export const trackViewItemList = (items, listName = 'Product Catalog') => {
  if (!Array.isArray(items) || items.length === 0) return;
  try {
    const ga4Items = items.map((prod, idx) => ({
      ...formatGA4Item(prod),
      index: idx + 1,
      item_list_name: listName,
    })).filter(Boolean);

    ReactGA.event('view_item_list', {
      item_list_name: listName,
      items: ga4Items,
    });
  } catch (err) {
    console.error('Error tracking view_item_list:', err);
  }
};

/**
 * Track select_item (Clicking a Product Card)
 */
export const trackSelectItem = (product, listName = 'Product Catalog') => {
  const item = formatGA4Item(product);
  if (!item) return;
  try {
    ReactGA.event('select_item', {
      item_list_name: listName,
      items: [{ ...item, item_list_name: listName }],
    });
  } catch (err) {
    console.error('Error tracking select_item:', err);
  }
};

 * Track view_item (Viewing Product Details Page)

/**
 * Track purchase (Completed Order)
 */
export const trackPurchase = (order) => {
  if (!order || (!order._id && !order.id && !order.invoiceNumber)) {
    console.warn('Aborting trackPurchase: Invalid order payload', order);
    return;
  }

  try {
    const rawItems = Array.isArray(order.items) ? order.items : [];
    const items = rawItems.map(item => {
      const prod = item.product || item;
      return formatGA4Item(prod, item.quantity || 1);
    }).filter(Boolean);

    const totalValue = typeof order.grandTotal === 'number'
      ? order.grandTotal
      : (typeof order.totalAmount === 'number' ? order.totalAmount : 0);

    const transactionId = String(order.invoiceNumber || order._id || order.id);

    ReactGA.event('purchase', {
      transaction_id: transactionId,
      currency: 'USD',
      value: totalValue,
      tax: order.tax || 0,
      shipping: order.shippingCost || 0,
      coupon: order.couponCode || '',
      items: items,
    });
  } catch (err) {
    console.error('Error tracking purchase:', err);
  }
};

7. Future Improvements (Best Practices)
User ID Stitching: Pass logged-in user IDs to GA4 via ReactGA.set({ user_id: user._id }) upon successful authentication, enabling cross-device user journey tracking in PlanPost.
Custom Dimensions: Define custom parameters (e.g. user_role, promo_code_applied) in GA4 for granular filtering in PlanPost reports.
Measurement Protocol Validation: Implement server-side verification using GA4 Measurement Protocol for high-value orders to prevent client-side ad-blockers from missing purchase hits.
Google Tag Manager (GTM) Abstraction: Consider migrating from raw GA4 tags to GTM container tags for enterprise-grade tag management and dynamic trigger adjustments without code redeployments.
